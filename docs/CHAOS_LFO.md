# Chaos LFO 实现与引擎验证（0.17）

本文记录 **0.17 Chaos LFO 当前约定范围的实现与交付**，源码、本机验收和发行包完整性复核均已完成。0.16 不包含 Chaos。原生检查发现的异步轨迹问题已修复并复查；最后一次捕获参数修复后的四套测试共 175 组通过，用时 135.03 秒，最终模块的 pluginval、音频对照及离线基准也已完成。下文区分自动化、原生观察及未覆盖范围；交付证据见 [0.17 验证记录](VALIDATION-0.17.md)。

## 声音模型

Lorenz 使用 `dx/dt = 10(y-x)`、`dy/dt = x(28-z)-y`、`dz/dt = xy-(8/3)z`。Rössler 使用 `dx/dt = -(y+z)`、`dy/dt = x+0.2y`、`dz/dt = 0.2+z(x-5.7)`。这是持续积分的动力系统，不是循环读取短波表，也不是 Random 的逐周期抽样保持。

方程参考 [Lorenz 1963 原论文](https://www.ita.uni-heidelberg.de/research/klessen/people/klessen/lectures/2008-A/CompPhys/lorenz_1963.pdf)及 [Rössler 1976 原论文](https://www.cfm.brown.edu/people/dobrush/am34/tutorial/AN-EQUATION-FOR-CONTINUOUS-CHAOS_ROSSLER.pdf)。[Serum 2 功能概览第 14 页](https://static.xferrecords.com/Serum%202%20What%27s%20New.pdf)列出这两种模式，但不公开其完整 DSP；以下速度、初态和输出映射是 Anyvoc 的定义，不代表 Serum 的算法或听感标尺。

每个名义周期分为 128 个固定 RK4 步，音频样点在相邻真实状态之间用三次 Hermite 插值读取。Lorenz 一个名义周期推进 1 个模型时间单位，Rössler 推进 6 个。采样率只决定读取时刻，不改变积分网格。这里的 Rate 表示**推进速度**，不表示混沌信号有固定基频或固定重复周期。

以从 0 开始的 LFO 索引 `i` 定义初态：Lorenz `(1+0.01i, 1, 1)`，Rössler `(1+0.01i, 0, 0)`。不做隐式预热，不依赖声部年龄或随机种子。因此相同初态、相同事件和时钟可以复现轨迹；每次真正触发后会经历进入吸引子的过渡过程。

调制源使用归一化后的 X。Lorenz 的 XYZ 映射为 `x/(10+abs(x))`、`y/(10+abs(y))`、`(z-25)/(25+abs(z-25))`；Rössler 对应使用分母常数 6、6、10，Z 先减 10。映射连续且有界，不用硬截断改变模型本身。

每次推进最多执行 128 个积分网格步，不分配内存。网格状态出现非有限值或任一坐标绝对值超过 `1e6` 时，保护逻辑恢复固定初态并增加恢复计数；下述正常轨迹测试中，恢复计数始终为零。此保护不同于输出的连续归一化，也不是抗混叠处理。

## 时钟与生命周期

| 操作 | 约定 |
| --- | --- |
| Free | 全局连续轨迹；MIDI 新音及宿主 PPQ 定位不重置混沌状态 |
| Trigger | 每次声部真实重触发从对应固定初态开始，持续积分，不在名义周期边界重置 |
| Envelope | 每次触发只推进一个名义周期后保持终点；末次步进裁到剩余时间 |
| Mono / Legato | 沿用原 LFO 声部触发规则：Mono 重触发，重叠 Legato 和回退延续；新声部/抢音重新初始化 |
| 切换算法或 Play Mode | 重置相应 Chaos 状态并清零 XYZ 读数；新模式尚无实际读取时保持零，避免显示旧模型的坐标 |
| Free Hz / Tempo / Audio Rate | 使用原有三个速度来源；Tempo 与 Follow Swing 改变积分推进量 |
| Phase / Direction / 相位目标 | Chaos 下不适用，忽略其音频影响并禁止相应 UI 操作，保留参数值以便切回 |
| 图形编辑和快捷曲线 | Chaos 下禁止绘制或套用 Custom 曲线；切回周期/Custom 类型后沿用既有行为 |
| 关闭 UI | 不影响积分、时钟或声音 |

必须保持旧波形在 Chaos 关闭时的音频路径；旧的 Shape、Kind、Random 序列与所有参数的自动化含义不应因新选项而改变。

保持同一 Play Mode 时，暂时选择 Chaos 不会暂停其背后的旧波形时钟：Free 的全局时钟、Trigger／Envelope 的声部时钟及其 Random 周期状态继续推进。切回后仍按原有同步规则读取，Envelope 的旧单次时钟到达终点后保持终点。切换算法重置 Chaos 的轨迹，不把旧时钟回到进入 Chaos 前的进度；更改 Play Mode 则沿用该模式自身的重置规则。

## 保存和界面

在旧 1,182 个参数之后按 LFO 1–10 的顺序追加 `lfoNChaos`，选项为 Off / Lorenz / Rossler，默认 Off，VersionHint 13。总参数数为 1,192，状态 schema 13；schema 1–12 缺少该项时使用 Off。当前格式缺失、重复或非有限参数必须在修改声音之前拒绝。

界面波形选择的有效编号沿用 0–5，6 为 Lorenz、7 为 Rossler。旧 Shape/Kind 的选项数量和序号保持不变；进入 Chaos 保留旧选择器，离开时先设置原波形，再关闭 Chaos。三项都纳入宿主回调冲突检查及同一步撤销。

动态图形读取声音引擎发布的归一化 XYZ，不在 UI 另跑积分器。图形只显示 UI 采集到的近期快照；高速变化时不能把有限刷新率的轨迹当成完整音频波形或频谱。每个音频块发布最后实际读取的坐标：Free 显示共享轨迹，Trigger／Envelope 显示最新活动声部。没有活动声部时不虚构新的运动。

XYZ、有效 Shape 和 Play Mode 在同一个 `generation` 内发布，读写这些数据及计数器的操作均使用 `seq_cst` 顺序一致内存序。读取前后必须得到相同的偶数代数，坐标和模式标签才算同一份完整快照。音频写端只执行固定数量操作，不阻塞、不等待 UI；UI getter 在遇到并发写入时重读，因此该 getter 供 UI 使用，不作为音频线程接口。

引擎接口 `getLfoChaosPoint(index, expectedShape = -1, expectedMode = -1)` 可按同一快照中的 Shape／Mode 过滤；负值为不限制，标签不匹配则返回全零。Editor 每次刷新先捕获本轮 Shape／Mode，再将这两个值经 Processor 原样传入 getter，并用于本轮轨迹缓存。这样即使参数切换早于下一音频块，或者宿主又在读取途中改变参数，也不会把另一算法或模式的点加入当前缓存。Processor 的无显式期望值调用仍按当前参数过滤。

算法／模式切换或引擎重置会清零已发布坐标和缓存；这里的全零是**本次模式时期尚无实际读取或快照标签不匹配**的哨兵，不表示 Lorenz／Rössler 的物理初态是 `(0,0,0)`。UI 收到它便清空历史，绝不把它追加为轨迹点；第一次真实且匹配的读取才开始新轨迹。Off 和非法 LFO 索引也返回零。精简视图和 Lab 绘制前还会检查缓存的 Shape、Mode 是否都匹配本次显示，避免在刷新间隔内绘制旧模式的线条。

## 已通过的引擎验证

[EngineTests 记录](engine-0.17.txt)为 **61 组、零失败**，包含原有 54 组与新增 7 组 Chaos 测试。最后一次修复后的 [完整测试记录](ctest-0.17.txt)共四套、175 组通过，用时 135.03 秒，其中 Processor 129.80 秒；[详细记录](test-details-0.17.txt)对应 Engine 61、Processor 98、Wavetable 10、Preset Library 6。引擎覆盖如下：

- **独立方程参考。** 测试独立定义方程、初态和输出映射；首个名义周期用每周期 32,768 步的细网格参考，对照生产 128 步 RK4 及每步内的 8 个读取位置，验证 Hermite 插值。原始坐标绝对误差上限分别为 Lorenz `4e-4`、Rössler `2e-6`，这是测试判据，不是长期轨迹误差保证。
- **持续演化与采样率。** 两种模型、全部 10 个初态各运行 2,000 个名义周期，检查有限值、原始坐标绝对值小于 100、归一化范围及零次保护恢复，并检查相隔 1 个及 64 个名义周期的轨迹未冻结或短周期重复。在 8／22.05／44.1／48／96／192 kHz 下，以 997 Hz 推进相同两秒时刻，归一化坐标差小于 `2e-6`。长时间混沌轨迹对数值误差敏感，这些检查不声称无限时长点对点相等。
- **生命周期与时钟。** 十个 LFO 的固定初态、重触发、偷音、Mono、Legato 重叠及回退、延音踏板、释放、Envelope 最后一步裁剪和终点保持；Free 的 PPQ 跳转不重置轨迹，Swing 改变推进速度；算法、模式、Off／On 切换及无活动声部时的坐标清理。
- **真实音频路径。** 高速 Chaos 作为主来源或 AUX 时，Pan 输出逐采样符合参考；经一采样延迟的相位调制链仍传递高速更新。Phase／Direction／相位目标对 Chaos 保持无效。未使用的 Chaos 不改变原有振荡器、Noise、Random LFO 的音频；块划分、重置及切回旧形状采用精确音频比较。
- **相干读数。** 并发发布／读取 XYZ 时，返回值必须完整属于某个实际 DSP 读点，不能拼接不同采样点的坐标。新增跨块标签回归检查算法／模式预期不匹配、切换及撤销后尚未渲染、首次新读取、重置和并发过滤；旧接口的通配读取仍可使用。

实现审查中修复了两项切换问题，并加入回归：逐声部 Chaos 原先没有推进背后的旧时钟，现已补齐，Saw／Random／Custom × Free／Trigger／Envelope × 两种 Chaos 共 18 种切回对照保持精确一致；另外，声部结束后切换算法原先可能保留旧模型的 XYZ，现已在新模式时期开始时清零，持续空渲染不会重新出现旧坐标。

原生独立版检查还复现了跨音频块的界面问题：Lorenz 切至 Rössler、Trigger 演奏后撤销回 Lorenz，界面一度收到旧 Rössler 坐标，随后收到零，残留了一条错误连线。原因是参数及界面选择先改变，而声音引擎在下一音频块才应用新模式；只保证 XYZ 自身一致不足以判断它属于哪个模式。修复因此覆盖整条读取链：在引擎快照内同时发布 Shape／Mode，按 Editor 本轮捕获的标签过滤，零哨兵清空历史且不入队，并在两种视图绘制时同时校验缓存 Shape／Mode。最后追加的捕获参数传递避免 Processor 再读参数时接受与本轮 UI 标签不同的更新快照。最终完整复测已通过，原生复查 Rössler 演奏后撤销回 Lorenz 时清零且未残留错误连线。

初轮另有一项重置音频对照失败，原因是测试将已经运行并重置的效果器与从未渲染的新效果器直接比较：JUCE Chorus 默认混合比例向目标渐变需 50 ms，Reverb 首次增益渐变需 10 ms。最终测试先让参照侧静音渲染 4,096 样本，再对两侧重置，保留全段逐样本差值 `== 0`，并增加 XYZ 精确相等检查；没有为此更改旧 DSP 或放宽容差。

## 离线性能实测

[完整基准记录](benchmark-chaos-0.17.txt)由最新构建的 `EngineTests --benchmark-chaos` 产生，已包含上述快照修复，测试机为 AMD Ryzen 7 9800X3D（8 核／16 线程），Windows x64 Release。共同条件为 48 kHz、256 样本块、16 个持续声部且起音错开、10 个 LFO、单个波表振荡器、Unison 1、滤波器与效果关闭。除最后一项无路由外，均为 10 条小强度 Pan 路由；每块调用 `setSettings`。每项渲染 2 秒音频，轮换顺序重复 3 次，排除构造与预热耗时，以下取各项中位数。

| 配置 | 渲染 2 秒音频的墙钟时间 | 墙钟时间／音频时长 |
| --- | ---: | ---: |
| Sine，10 Hz，Trigger | 0.256302 秒 | 0.128151 |
| Lorenz，10 Hz，Trigger | 0.350042 秒 | 0.175021 |
| Rössler，10 Hz，Trigger | 0.350398 秒 | 0.175199 |
| Sine，1,000 Hz，Trigger | 0.294062 秒 | 0.147031 |
| Lorenz，1,000 Hz，Free | 0.300455 秒 | 0.150228 |
| Lorenz，1,000 Hz，Trigger | 1.210367 秒 | 0.605183 |
| Rössler，1,000 Hz，Trigger | 1.198819 秒 | 0.599409 |
| Rössler，1,000 Hz，Trigger，无路由 | 1.099535 秒 | 0.549767 |

极端 Trigger 配置明显比 Free 昂贵：Free 共享 10 条轨迹，16 声部的 Trigger 同时推进 160 条。**当前没有按路由需求停算 Chaos 的优化**，最后一项即使完全未接入矩阵，仍执行全部 160 条积分；若不需要某个 Chaos，关闭它才能停止其模型计算。

`0.605183` 表示平均渲染 1 秒音频用了约 0.605 秒墙钟时间，不是整机 CPU 使用率，也不能按核心数直接分摊。这是指定硬件与简单音色下的离线平均值，不能证明每个实时音频块都满足期限，更不能证明不同驱动、较小缓冲、其他宿主或更复杂音色下无掉音。多振荡器、高 Unison、滤波器和效果还会增加成本；1,000 Hz 的复杂逐声部用法仍应谨慎评估。固定积分步数上界不等于实时性能保证，也不消除高速调制的混叠。

## 本机验收与交付边界

最终 VST3 通过 [pluginval strictness 5](pluginval-0.17.txt)，随机种子为 `0x5f5ab2b`，结果为 SUCCESS。[独立音频分析](audio-analysis-0.17.json)确认旧演示与 0.16 参照逐字节一致；新 20 秒演示以相同 MIDI、速度和增益对比 Lorenz／Rössler，最后一次修复后重渲染的 PCM 哈希仍相同。已生成 80 张预览，其中 6 张 Chaos 标准／最小尺寸图逐张检查未见裁切。这些记录与上面的四套测试共同覆盖源码和本机验收，不能替代真人听音或实际 DAW 使用。

原生鼠标操作已检查：选择 Butterfly Current，屏幕 C4 在两种 Chaos 下均有绿色电平；Rössler 演奏后撤销回 Lorenz 清零且无错误连线；Chaos 下拖动 Phase 后仍为 0，Speed 1.80→7.29 后撤销回 1.80；Free 持续演化，Envelope 短音后 XYZ 稳定；切回 Sine 恢复控件后再撤销，最小窗口检查完成。Envelope 的原生观察没有测量整名义周期，其精确推进和终点保持由引擎测试验证。退出后恢复原设置，并核对 SHA 与检查前一致。

Windows 包包含 190 个文件，完整源码包包含 4,580 个文件。CRC、安全且唯一的路径、精确文件集合及逐文件字节一致性均通过；构建与包内 EXE／VST3 的四个 PE 版本均为 0.17.0，包内二进制哈希匹配最终构建。报告 `Anyvoc-0.17.0-PackageVerification.json` 外置于发行包目录。P1A 当前约定范围交付完成，详见 [0.17 验证记录](VALIDATION-0.17.md)。

本轮没有真人听音、原生保存／加载重测和 DAW 验收；文字搜索因 CUA 未能传递输入而未验证。0.17 提交 `f20c1aa` 的云端干净构建及 175 组测试已通过，见[云端记录](GITHUB_CI-0.17.md)。实际设备、驱动、宿主及实时缓冲表现不能由离线基准推定；P1B 绘图工具、P1C 宏作为目标及更多目标仍是后续计划。
