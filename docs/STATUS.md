## 这次改善了什么

ARP 开启时，引擎直接读取处理器的私有 MIDI 缓冲，不再与宿主缓冲交换存储；关闭时仍读取宿主 MIDI，回调末尾仍清空宿主输出。最小生产改动只涉及 Processor `.cpp/.h` 的返回引用及接线，不改参数、schema、预设和引擎声音算法。[诊断方法](MIDI_ALLOCATION_PROFILING.md)明确四个 CRT 调用点及其限制。

## 已有能力与主要缺口

下表概括当前实现范围，交付结论仅限上述实际检查。

| 范围 | 已有能力 | 主要边界 |

| 声源 | 三个波表／采样／颗粒振荡器、Sub、Noise；16 复音、1–7 路 Unison | 没有多采样键区、SFZ 或频谱振荡器；采样导入最长 20 秒，变调与插值质量仍需改进。 |
| 波表与 Warp | 每帧 2,048 点、最多 32 帧；绘制、谐波幅相、渐变、导出；双层 Warp 与 FM/PM/AM/RM | 公式工具、更多算法与完整过采样抗混叠未实现。 |

## 恢复后待办（暂停期间不执行）

1. 先核对 0.20.4 最终包外报告与实际推送 head 的 CI；设备释放后另补原生演奏和六负载三轮测量。ARP 分配与矩阵缓存已有各自精确声音回归，不能据此称全回调零分配或超预算已解决。随后逐项优化 Chaos／颗粒并覆盖其他缓冲、声卡和 UI 条件。
2. 扩大多声源与多素材的重启恢复检查，继续缩减历史间歇性琶音问题；离线通道回归不等于外接设备与所有输入情形都已验收。
3. 在改善实时可靠性后扩展明确的调制目标，再推进多采样、频谱声源与效果总线。用户需要 DAW 时先验证 FL Studio。阶段与完成条件见[路线图](ROADMAP.md)。

目前没有外接 MIDI、真人听音或跨 DAW 的验收结论。0.20 单份采样的实际进程重启验证不等于所有外部素材恢复通过；离线平均性能不保证实时无掉音。
