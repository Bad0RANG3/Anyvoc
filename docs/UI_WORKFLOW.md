# Anyvoc 音色设计工作流

本文记录 **0.20** 中 `Source/PluginEditor.cpp` 的 PLAY 页与导航约定。目标是让第一次接触合成器的人先听到声音、理解少量常用控制，再逐步进入完整编辑器。PLAY 与其他页面操作的是同一份音色。实际已执行范围见 [0.20 验证记录](VALIDATION-0.20.md)；下方为验收标准，逐项执行状态以验证记录为准。

## 从试听到完整编辑

编辑器默认打开 PLAY，顶部导航按 `PLAY / SYNTH / FILTER / MOD / FX` 排列。

| 页面 | 使用目的 |
| --- | --- |
| PLAY | 选择音色、试听，调整音色明暗、音符起落和空间感。 |
| SYNTH | 选择与叠加音源，编辑波表、采样、颗粒、Warp 和发声方式。 |
| FILTER | 编辑双滤波器及各音源的滤波路由。 |
| MOD | 编辑包络、LFO 和完整调制矩阵，让参数随时间或演奏变化。 |
| FX | 编辑饱和、合唱、延迟与混响。 |

这个顺序表达编辑工作流，不代表 MOD 是音频串联处理的一环；实际滤波路径仍由 FILTER 中的路由设置决定。

PLAY 顶部显示已加载的音色。`CHOOSE A SOUND` 与顶部 `BROWSE` 打开同一音色浏览器：选择条目不立即替换当前音色，需执行 `LOAD SOUND`、双击条目或使用浏览器支持的 Return 操作。底部琴键始终试听已加载的音色，也可以从宿主或 MIDI 键盘演奏。性能宏、琴键、主音量与输出电平在各编辑器之间持续可用。

PLAY 下方的 `GO DEEPER` 提供 `SOURCES / SYNTH`、`TONE / FILTER`、`MOVEMENT / MOD`、`FINISH / FX` 四个入口。卡片里的 EDIT 打开与当前控制相关的完整编辑器。

## PLAY 控制的真实含义

PLAY 没有另建一套简化音色参数，也没有为常用旋钮添加隐式宏映射。它通过已有参数附件直接编辑下表中的参数，其他页面与宿主自动化应同步显示同一个值。

| 区域与控制 | 已有参数 | 使用约定 |
| --- | --- | --- |
| TONE：ON / OFF | `filterEnabled` | 开启或旁通 Filter A。保留滤波参数，不修改音源路由或 Filter B。 |
| TONE：CUTOFF | `cutoff` | Filter A 的截止频率。低通时可理解为明暗，高通与带通时以当前滤波类型说明为准。 |
| TONE：RESONANCE | `resonance` | 加强截止频率附近的成分。 |
| NOTE SHAPE：ATTACK | `ampAttack` | 振幅包络的起音时间。 |
| NOTE SHAPE：DECAY | `ampDecay` | 振幅包络从峰值下降至持续电平的时间。 |
| NOTE SHAPE：SUSTAIN | `ampSustain` | 按住音符期间的持续电平；它不是持续时间。 |
| NOTE SHAPE：RELEASE | `ampRelease` | 松开音符后的衰减时间。 |
| SPACE：ECHO | `delayMix` | 延迟的干湿混合比例；时间与反馈在 FX 中编辑。 |
| SPACE：REVERB | `reverbMix` | 混响的干湿混合比例；空间大小在 FX 中编辑。 |

Filter A 只影响实际经过它的音源。PLAY 显示这一限制；旁通时 CUTOFF 与 RESONANCE 变暗且不可编辑，重新开启后继续使用原有设置。需要检查声音为何不受影响时，使用 TONE 的 EDIT 查看 FILTER 路由。

NOTE SHAPE 的包络图或 EDIT 打开完整振幅包络编辑器。启用 `ampTempoSync` 后，PLAY 的 ATTACK、DECAY、RELEASE 显示对应节拍长度并禁止直接修改秒值；通过 EDIT 修改同步阶段长度。SUSTAIN 仍然是可编辑的电平。切回秒模式后恢复已有秒值的编辑。

此次 UI 工作流调整保留原有完整参数、音源编辑能力和预设格式。打开 PLAY、切换页面、打开编辑器本身不应改变音色参数或创建音色 Undo 记录；主动编辑旋钮、开关、曲线或加载音色继续遵循已有历史机制。

## 在 PLAY 添加调制

`MOD SOURCES` 明确表示调制来源，避免与 SYNTH 中的发声音源混淆。它打开现有来源面板，包括十个 LFO、四个包络、八个宏及演奏来源。顶部常用来源芯片仍可直接操作。

1. 在 PLAY 启用 Filter A，并试听一个音符。
2. 将顶部 LFO 芯片，或 MOD SOURCES 面板中的来源，拖到高亮的 CUTOFF、RESONANCE 或底部宏旋钮。
3. 拖拽开始后来源面板收起，PLAY 保持当前页，不强制跳到 SYNTH。
4. 拖动目标旋钮的彩色外环调整所选路由的深度；Shift 提供精细调整。旋钮本体继续编辑参数基础值。
5. 右键目标查看与编辑已有路由，或进入 MOD 查看完整矩阵。一个目标可以具有多个路由；当前外环表示选中来源对应的一条路由，不表示所有路由之和。

PLAY 的 ADSR、ECHO、REVERB 并未因此成为新的拖拽调制目标。可接受的目标沿用已有调制能力；新手页不扩展或替换引擎路由语义。

## 验收清单

以下是完整验收要求，不能由一项通过推断全部通过。本轮已执行的独立版限定原生检查见 [PLAY 原生记录](ui-play-native-0.20.json)：默认页、滤波旁通与跨页撤销、BPM 显示、打开包络面板时的调制拖放、最小窗口、琴键输出活动和浏览器入口。记录包含实际二进制哈希及未测范围；完整自动回归结果由主版本验证报告统一记录。

- 新建编辑器默认显示 PLAY，五个导航入口按 `PLAY / SYNTH / FILTER / MOD / FX` 排列且选中态正确。
- 在最小尺寸 `1008 × 684`、默认尺寸 `1120 × 760` 与最大尺寸 `1568 × 1064` 检查导航、卡片、说明文字、GO DEEPER、宏、键盘与输出区；不得遮挡、裁切或出现不可点击的入口。
- PLAY 的 CUTOFF、RESONANCE、ADSR、ECHO、REVERB 分别更新对应真实参数；进入 SYNTH、FILTER、FX 后值一致，宿主自动化反向更新 PLAY。
- Filter A 旁通后，PLAY 的截止频率与共振不可编辑且显示旁通提示；重新开启恢复原值，不修改 Filter B 或音源路由。只路由到 Filter B 的声音不能被误认为也经过 Filter A。
- 浏览、选中但不加载音色不改变声音；显式加载后，PLAY 音色名称与底部试听对应实际已加载的音色。
- 从 PLAY 拖动常用来源及 MOD SOURCES 中的来源时保持 PLAY；合法目标可接受拖拽，外环深度可编辑，MOD 能看到对应路由。
- 一次旋钮拖拽只形成一次音色 Undo；Undo / Redo 后 PLAY 与完整编辑器数值同步。导航和选择调制来源不增加音色历史，宿主更新不被当成新的用户编辑。
- 开启振幅包络 BPM 同步后，ATTACK、DECAY、RELEASE 显示节拍长度并阻止秒值写入；SUSTAIN 仍可编辑；EDIT 中调整阶段长度后显示同步更新。关闭 BPM 同步恢复秒值编辑，不意外覆盖原秒值或节拍设置。
- 检查包络、音源、调制和 FX 的上下文 EDIT 打开正确目标；返回 PLAY 后宏、键盘与输出继续可用，声音状态保持一致。
- 原有 UI 回归测试需要进入 SYNTH 时显式选择该页，不能再依赖初始页；重点覆盖波表、Warp、调制外环、Voicing 和 `openEnvelopeLab()` 测试助手。截图生成中的重新创建编辑器路径也须显式选择目标页。

## 持音试听的后续约定

本次不加入 HOLD C4。现有点击琴键与 MIDI 演奏路径继续使用。长期持音试听需要专门的生命周期 API，不能只在 UI 保存一个开关并调用 `keyboardState.noteOn/noteOff`。

当前引擎普通复音按通道与音高处理 note-off，但同通道同音高的多个声部会一起释放；JUCE 键盘状态对每个通道与音高只记录一个布尔状态。当前 ARP 的输入保持状态仅按音高记录，不区分通道，因此换用通道 16 也不能隔离真实 C4 与试听 C4。panic 会重置键盘状态与待发事件，而预设或其他声音重置不一定同步清除 UI 键态。

未来接口应明确拥有试听音，区分试听与外部 MIDI，并统一处理重复同音、ARP、Mono / Legato、延音踏板、预设与工程状态替换、宿主停止、panic 和编辑器关闭。停止试听只释放试听拥有的声音，不能通过全局 panic 中断真实演奏；重置完成后应向 UI 提供准确状态，避免显示“正在持音”却已静音，也不能在重置后意外重新触发声音。实现与相关生命周期验证完成后，再开放持续试听控件。
