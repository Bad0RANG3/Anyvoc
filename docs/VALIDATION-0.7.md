## Preset persistence and library scope

State schema remains 6, adding optional `presetName` and `presetId` properties. A legacy state with neither property derives its display identity from the stored factory program; partial or invalid identity metadata rejects the whole state without mutation. Explicit file loads use the actual filename/path rather than trusting embedded identity. Preset saves write a separate `.tmp` file beside the destination and replace the destination only after writing succeeds; active identity is published only on success. A Windows file lock was used to verify failed replacement leaves the old destination and active sound intact.

The browser indexes file names and first-level folder categories off the audio callback, without parsing embedded wave/sample data. Default library: Documents/Anyvoc/Presets. Favourites: user application-data Anyvoc/preset-library.xml, protected by in-process and inter-process locks and atomic replacement. Refresh rereads settings to merge changes from other instances. Scanning is bounded to depth 8, 10000 directories and 50000 encountered filesystem items; limits/errors report partial results. Favourites follow factory names or user file paths; moving/renaming a file does not transfer its favourite. Author/tag editing, automatic recorded audio previews, multiple library roots and global undo remain unimplemented.

## Delay boundary correction

Comparing the retained actual v0.5 executable with the initial v0.6 render exposed a sample-preset difference beginning at the first 0.3-second echo. Investigation found an existing out-of-bounds read: at 48 kHz, float `0.3 * 48000` is approximately 14400.00098; adding the 100808-frame ring length to a slightly negative float read pointer can round to exactly 100808, making the array index equal to its length.

The production read pointer now uses double precision, wraps and clamps valid indices, and interpolates across the last-to-first sample boundary. The regression uses an independent, unbounded history of dry samples to calculate the expected delayed signal, checks every stereo sample beyond a full ring wrap at 44.1/48/96 kHz, and warms up the effects with silence before note onset to settle JUCE's initial dry-gain ramp. Maximum absolute errors were 9.31956e-9, 9.08024e-9 and 8.83901e-9 respectively, below the unchanged 2e-6 limit. The fixture requires a measurable attack and nonzero signal around the later boundary.

Legacy patch parameters still migrate, but delay-enabled audio is not claimed byte-identical to v0.5 after this correction. The historical intermittent arp-sustain observation above has no demonstrated causal link to this bug.

## Scope

This validates an original wavetable/sample/granular instrument, not equivalence to Serum 2. A pluginval pass is not a guarantee of compatibility with every DAW or every host workflow. Factory oscillator tables are mipmapped; final saturation is not oversampled, so extreme drive can alias. Warp uses smoothed fractional mip selection and removes only the DC introduced by the warped-minus-raw signal; Sync, Mirror and Fold are not fully bandlimited. Warp's static display excludes live modulation, DC correction, pitch-dependent mip selection and downstream processing, and does not modify exported source tables. Imported samples are limited to 20s, 8–192 kHz, mono/stereo, resampled offline to 48 kHz with a windowed-sinc low-pass; live pitched sample/grain playback uses interpolation without mipmapped anti-aliasing. Sample/grain pools are fixed-size and imported-buffer retirement occurs on the writer thread, but shared-pointer atomics do not establish a hard real-time guarantee. Worst-case live CPU has not been benchmarked. Multisample/SFZ mapping, spectral synthesis, cross-source FM/PD, expanded modulation and effects buses, Clip sequencing and complete preset browsing/global undo remain outside the implemented feature set.
